# B 이달의 생활숫자에 '이달의 지하철 숫자'(④ 코너) 붙이는 법

작성 2026-11-23 · 만든 곳: `claude\subway-sampler` · 이 문서 사본: `life-numbers\docs\지하철숫자_붙이기.md`

## 무엇을 쓰나

평일 아침(07~09시) 관측으로 한 달에 한 꼭지를 씁니다. 블로그 본문과 인스타 카드 모두에 쓸 수 있습니다.

| facts 키 | 단위 | 뜻 |
|---|---|---|
| `지하철_관측_평일수` | 일 | 이달 통계에 쓴 평일 수 |
| `지하철_8시_운행열차` | 대 | 08시 무렵 한 순간에 위치가 잡힌 열차 수(받는 14개 노선) |
| `지하철_출근배차_가장촘촘_초` | 초 | 노선별 출근 배차 중간값 중 가장 짧은 값(노선 이름은 `주의`와 표) |
| `지하철_출근배차_가장성김_초` | 초 | 가장 긴 값 |
| `지하철_급행비율_○○` | % | 급행이 서는 역 기준 급행 비율(5% 이상인 노선만) |
| `지하철_가장긴_공백_초` | 초 | 옆 역에서도 같은 시간에 비어 있던 가장 긴 공백 |

표: `지하철_노선별_출근배차`(노선·배차_중간값_초·시간당_열차·급행_비율_%), `지하철_긴공백_TOP5`(역·노선·시각·공백_초·날짜).

## 붙이는 순서 (B 세션에서)

1. **읽기**: `build_facts.py`에서 `subway-sampler\export\life_numbers\{데이터 달}.json`이 있으면 읽습니다. A 폴더를 읽기만 하는 방식과 같습니다.
   - `항목`은 facts `항목`에, `표`는 facts `표`에, `출처["④"]`는 facts `출처`에 더합니다. 지하철 항목은 실데이터라 `예시_코너`에는 넣지 않습니다(`예시: false`).
   - 파일이 없거나 `관측_평일수`가 10일 미만이면 '이번 달 쉼'으로 메모합니다(다른 코너와 같은 규칙).
   - 호와 달: 2027-01호 = 2026-12 관측입니다(B의 `--data-ym` 규칙과 같음).
2. **단위**: `factlib.py`에 단위 `초`·`대`를 더합니다. `초`는 화면에 "2분 30초"로 씁니다(`fmt_sec`, 아래 예시).
   ```python
   def fmt_sec(v):
       v = rnd(v); m, s = divmod(v, 60)
       return f"{m}분 {s}초" if m and s else (f"{m}분" if m else f"{s}초")
   ```
3. **verify**: 초안의 "2분 30초" 표기를 150초로 바꿔 facts와 대조합니다. "대"는 `fmt_count(v, "대")`로 쓰면 기존 대조를 그대로 탑니다.
4. **초안 템플릿**: `drafts/templates/4_지하철.md`를 새로 만듭니다. 예시 문장(숫자는 모두 facts 자리표시):
   - "12월 평일 아침 8시 무렵, 서울 지하철 위에는 {지하철_8시_운행열차}대가 달리고 있었습니다."
   - "출근 시간 열차가 가장 자주 온 노선은 {노선}으로, 보통 {지하철_출근배차_가장촘촘_초}마다 왔습니다."
   - "가장 오래 비었던 때는 {날짜} {시각} {노선} {역}역, {지하철_가장긴_공백_초} 동안 열차가 오지 않았습니다."
   - 끝에 "평일 07~09시, 4분 간격 열차 위치 관측으로 추정한 값"과 출처를 씁니다.
5. **사람 확인 한 겹**: 긴 공백 1위는 그날 뉴스(고장·사고)를 한 번 찾아 '직접 확인한 것'에 적습니다. 원인을 모르면 원인은 쓰지 않습니다.

## 주의

- "정시율", "지연"은 쓰지 않습니다. 시간표와 비교한 값이 아니라 관측 간격이기 때문입니다.
- 순위 표현("가장 성긴 노선")은 받는 14개 노선 안에서의 비교라고 밝힙니다(공항철도·경춘선은 한도 때문에 빠짐).
- 이 파일을 만드는 명령: `python pipeline/export_life.py --ym 2026-12` (subway-sampler 폴더에서). 자동 수집 워크플로가 매일 이번 달 파일을 새로 만듭니다.
